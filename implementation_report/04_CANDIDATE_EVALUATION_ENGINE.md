# 04 — Candidate Evaluation Engine (Shadow Evaluator)

## Purpose

Evaluates the candidate's spoken answer against a technical rubric
without blocking the voice audio stream. Runs as a background asyncio task.

## Location

File: app/evaluator_engine.py
Function: evaluate_candidate_response()
Called from: live_server.py run_shadow_pipeline() -> asyncio.create_task()

## Inputs

| Input | Source |
|-------|--------|
| skill | active_topic (current knowledge graph node) |
| interviewer_question | alex_latest_question (last Alex spoken text) |
| candidate_answer | user_text (Gemini STT transcript) |
| scaffolding_level | policy_router.current_scaffolding_level |
| ecosystem_context | get_evaluator_ecosystem_context() |

## Processing

Sends a structured prompt to Gemini REST API (gemini-3.1-flash-lite):

Rubric dimensions:
1. Concept Depth — underlying principles and abstractions
2. Practical Implementation — concrete tools, patterns, ecosystem-specific idioms
3. Trade-off Awareness — failure modes, complexity, system trade-offs
4. Technical Relevance & Focus — directly addressed prompt; off-topic = observation:0, depth:0.10

Response schema enforced via response_mime_type="application/json"

## Output (structured JSON)

```json
{
  "observation": 1,           // 1=passed, 0=failed/struggling
  "depth_score": 0.85,        // 0.0 to 1.0 (or 0 to 100, normalised server-side)
  "estimated_difficulty": 0.4, // -1.5 (very basic) to +2.5 (staff frontier)
  "summary": "...",           // 1-2 sentence assessment
  "rubric_items": [
    {"criterion": "Core Concept Depth", "passed": true, "note": "..."},
    {"criterion": "Practical Implementation", "passed": true, "note": "..."},
    {"criterion": "Trade-off Awareness", "passed": false, "note": "..."},
    {"criterion": "Technical Relevance", "passed": true, "note": "..."}
  ],
  "recommended_probe": "..."
}
```

## Timeout and Fallback

- Timeout: 6.5 seconds (asyncio.wait_for)
- Fallback on exception:
  - observation = 1 if answer > 15 words, else 0
  - depth_score = 0.70 if pass, else 0.35
  - No rubric items with depth

## Critical Limitation: Rubric Not Pre-Locked

The rubric is generated by the same LLM call that sees the candidate's answer.
This means the evaluation criteria are NOT established before the answer is seen.
The LLM could theoretically be influenced by the answer content when deciding rubric outcomes.

CURRENT IMPLEMENTATION: Rubric generated post-answer (answer-aware)
PROPOSED IMPROVEMENT: Generate rubric before sending question; freeze criteria; then evaluate

## Evaluation Isolation

The candidate answer is placed inside a labelled quoted field:
  Candidate Answer: "{candidate_answer}"

It is NOT placed in the system instruction or injected as unmarked instructions.
The LLM is instructed to evaluate it, not follow it.

## Failure Scenarios

| Scenario | Behavior |
|----------|---------|
| LLM timeout (>6.5s) | Fallback: word count heuristic |
| Invalid JSON | Exception -> fallback |
| Off-topic/trivial answer | observation:0, depth_score:0.10 (per rubric instruction) |
| Empty answer | observation:0 (word count < 15) |
| Prompt injection in answer | Evaluated as answer data; LLM given explicit instructions not to follow it |
